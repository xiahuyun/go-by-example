# 文件锁（File Lock）示例

这是一个使用 Go 语言实现的文件锁示例，演示了如何使用 `syscall.Flock` 进行文件锁定操作。

## 核心特性

- **阻塞锁**：当锁被占用时会阻塞等待
- **非阻塞锁**：尝试获取锁，失败时立即返回
- **基于文件描述符**：锁状态与文件描述符关联，而非进程
- **协程安全**：可以在多个协程间使用

## 核心概念：flock 锁的工作原理

### 基于文件描述符的锁

**重要概念**：`flock` 系统调用创建的锁是与文件描述符关联的，而不是与进程或协程关联的。这意味着：

- 同一个进程内的多个协程如果使用同一个文件描述符，它们会共享锁状态
- 只有使用不同文件描述符（即使指向同一个文件）的协程/进程才会产生真正的锁竞争
- 当文件描述符关闭时，关联的锁会自动释放

### 锁类型

- **LOCK_EX**：排他锁，同一时间只有一个进程可以持有
- **LOCK_SH**：共享锁，多个进程可以同时持有
- **LOCK_NB**：非阻塞模式，获取不到锁时立即返回错误

## 主要功能

### FileLocker 结构体

```go
type FileLocker struct {
    file *os.File
}
```

### 核心方法

- `NewFileLocker(filename string) (*FileLocker, error)`：创建新的文件锁实例
- `Lock() error`：获取阻塞排他锁
- `TryLock() error`：尝试获取非阻塞排他锁
- `Unlock() error`：释放锁
- `Close() error`：关闭文件

## 使用示例

### 基本用法

```go
// 创建文件锁
locker, err := NewFileLocker("test.lock")
if err != nil {
    panic(err)
}
defer locker.Close()

// 获取锁
if err := locker.Lock(); err != nil {
    fmt.Printf("加锁失败: %v\n", err)
    return
}

// 处理临界区代码
time.Sleep(2 * time.Second)

// 释放锁
locker.Unlock()
```

### 非阻塞锁示例

```go
// 尝试非阻塞加锁
if err := locker.TryLock(); err != nil {
    if err == syscall.EWOULDBLOCK {
        fmt.Println("锁被占用，等待后重试...")
        // 等待后使用阻塞锁
        time.Sleep(1 * time.Second)
        if err := locker.Lock(); err != nil {
            fmt.Printf("加锁失败: %v\n", err)
            return
        }
    } else {
        fmt.Printf("加锁失败: %v\n", err)
        return
    }
}
```

## 演示场景

本示例演示了三个协程竞争同一个文件锁的场景：

1. **协程1**：获取阻塞锁并持有5秒
2. **协程2**：等待0.5秒后尝试非阻塞加锁
3. **协程3**：等待0.5秒后尝试非阻塞加锁

### 注意事项

1. **文件描述符共享问题**：
   - 同一个文件锁实例在多个协程间共享时，它们会共享锁状态
   - 要实现真正的协程间锁竞争，需要为每个协程创建独立的文件锁实例

2. **锁的自动释放**：
   - 当文件描述符关闭时，关联的锁会自动释放
   - 使用 `defer locker.Close()` 确保锁被正确释放

3. **跨进程锁**：
   - flock 锁可以在不同进程间使用
   - 不同进程打开同一个文件时，会产生真正的锁竞争

## 技术细节

- **系统调用**：使用 `syscall.Flock` 实现文件锁定
- **文件操作**：使用 `os.OpenFile` 打开或创建锁文件
- **并发控制**：使用 `sync.WaitGroup` 等待所有协程完成

## 适用场景

- **进程间同步**：多个进程需要访问共享资源时
- **防止重复执行**：确保同一时间只有一个实例运行
- **临界区保护**：保护需要独占访问的代码区域
